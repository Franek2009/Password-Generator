## Implemented scope

Both platforms provide optional minima, literal custom/forbidden ASCII alphabets,
first/last character types, identical-run limits, exact uniform advanced sampling,
localized validation and a collapsible native rules section. Rules are persisted
separately and included in versioned random-mode presets with lazy v1 migration.
CPU work is cancellable and never publishes a stale result after configuration
changes. Transcription copies the original; passphrases and classic generation
retain their previous behavior. Desktop opens 40 px taller to keep the primary
action visible with the added collapsed row; narrow viewports remain scrollable.

Lint warnings concern dependency versions (6), checked SharedPreferences commit
calls (2), existing backup rules (1), SDK condition (1) and monochrome icon (1).
No Android lint error was suppressed to achieve this result. The worker's broad Python
exception handler is explicitly marked as an error-reporting boundary; it does
not log exception content or passwords.

Independent exhaustive tests enumerate small alphabets and every admissible rank;
shared fixtures include huge exact counts and closed-form expectations. Statistics
are auxiliary evidence, not a proof of uniformity or cryptographic security.

[Python benchmarks](evidence/python-benchmarks.json) measure **counting**, in fresh
processes, including interpreter RSS: typical 12 ms; listed hard cases 1.08–1.29 s;
peak process RSS below 80 MiB. They do not measure full desktop generation or
Windows performance. [Android measurements](evidence/android-engine-metrics.txt)
include compilation, exact counting, secure rank selection and unranking. All six
listed cases meet 2 s / 128 MiB sampled extra heap **on this emulator**. Heap is
sampled, so this is not a formal bound on every transient allocation or every
possible configuration. Cold-run optimization evidence was previously 0.72–1.45 s
and at most 86 MiB sampled extra heap; these are development measurements, not a
physical-phone result.

## Not verified / remaining acceptance

* Reference-phone speed/memory, including typical <200 ms and hard <=2 s / 128 MiB.
  No authorized physical device was available in the final ADB device list.
* Native Windows build, execution, font rendering and clipboard behavior.
* Manual TalkBack/desktop reader sessions, large system font scaling and uncommon
  keyboards. Automated tests cover control names, semantics, raw copy, narrow
  layout, mode changes and cancellation, not a complete accessibility audit.
* A full instrumentation run on minimum supported API 26. Current device evidence
  is API 35; compilation retains minSdk 26.
* Deliberately failing Android disk writes were not injected in instrumentation.
  Production checks commit results; Python exercises its write-failure path.
* The independent audit requested by the owner. The developer review above is
  not a substitute for it, or a declaration that the release is ready to publish.

## Reproduce checks

```sh
QT_QPA_PLATFORM=offscreen QT_QPA_PLATFORMTHEME= python -m pytest
python scripts/benchmark_advanced.py
python scripts/check_advanced_statistics.py
git diff --check
./android/gradlew -p android testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Instrumentation was run after installing both debug APKs on the task emulator:

```sh
adb -s emulator-5590 shell am instrument -w \
  pl.franek.passwordgenerator.test/androidx.test.runner.AndroidJUnitRunner
```

Build commands and artifact paths are recorded in `evidence/builds.json`. No
signing configuration, release workflow, license or provenance-audit mechanism
was changed. No dependencies or permissions were added to the application.
