# Przegląd przed wydaniem v1.2.0

Data: 2026-11-01. Kod poddany przeglądowi: `e1c396678bf36d83ba57b07a586e0b38a6e4e515`.
Raport przygotował asystent wdrażający zmiany. Jest to przegląd implementacyjny
z dowodami testów, nie niezależna certyfikacja bezpieczeństwa.

## Zakres i ustalenia

Sprawdzono generatory, konfigurację, serializację presetów, kopiowanie wyniku,
obsługę słowników, interfejsy obu platform oraz konfigurację buildów i wydania.

- Losowość nadal pochodzi z `secrets` / `SecureRandom`; każdy wybrany zestaw
  znaków jest reprezentowany także po wykluczeniu `0Oo1Il`.
- Presety mają wersjonowany format i jawnie dozwolone pola. Odczyt sprawdza
  typy, zakresy, nazwy, identyfikatory, separatory i konfigurację zestawów.
  Błędne dane nie są automatycznie nadpisywane; wbudowanych presetów nie usuwa się.
- Zapisywane są parametry generatora i preferencje; nie jest serializowany wynik
  ani cały stan UI. Testy sprawdzają brak kontrolnych haseł i fragmentów w zapisie.
- Grupowanie i zawijanie tekstu są wizualne. Kopiowanie korzysta z oryginalnej
  wartości, także dla niestandardowych spacji w słowach.
- Zmiana trybu czyści wynik. Android unieważnia zakończone z opóźnieniem zadania
  po zmianie konfiguracji. Zastosowanie presetu nie generuje ani nie kopiuje hasła.
- Zewnętrzny słownik jest ponownie odczytywany przy zastosowaniu presetu
  i generowaniu; brak pliku lub dostępu zgłasza błąd bez zastąpienia słownika.
- Pisownia słów jest zgodna między platformami: wielka pierwsza jednostka Unicode,
  pozostałe znaki bez zmian, niezależnie od systemowego locale i wykluczeń.
- Nie dodano telemetrii, historii ani połączeń sieciowych do aplikacji;
  manifest Androida nie żąda INTERNET. Automatyczne kopiowanie jest domyślnie wyłączone.
- Licencje, provenance audit, Corresponding Source, klucz APK i workflow wydania
  pozostały bez zmian. Wersje aplikacji nadal powstają z taga.

Przegląd nie wykazał otwartego błędu funkcjonalnego wymagającego poprawki kodu.
Nie oznacza to wykonania wszystkich scenariuszy ręcznych wymienionych niżej.

## Ograniczenia i ręczny odbiór

Użytkownik zgłosił brak zauważonych błędów podczas własnego sprawdzania. Nie
otrzymano protokołu pozwalającego uznać poniższe szczególne scenariusze za zaliczone:

- ręczny przegląd TalkBack i czytnika desktopowego;
- pełny wybór pliku w selektorze systemowym i późniejsze cofnięcie wcześniej
  udzielonego trwałego uprawnienia do tego samego URI;
- wyczerpujący ręczny przegląd interfejsu Windows we wszystkich konfiguracjach.

Test niedostępnego URI nie dowodzi rzeczywistego cofnięcia trwałego grantu.
Powyższe pozycje pozostają jawnie niezweryfikowane. Szczegóły i instrukcje:
[karta odbioru](v1.2.0-validation.md).

## Ostrzeżenie Windowsa

Użytkownik zgłosił ostrzeżenie przy poprzednim EXE. Bez dokładnego komunikatu nie
zakwalifikowano go jako SmartScreen ani fałszywego wykrycia antywirusowego.
Paczka Windows nadal nie ma podpisu Authenticode. SmartScreen ocenia reputację
pliku i wydawcy, więc nieznana reputacja może wywołać ostrzeżenie także dla nowego
buildu. Sam build lub brak znanych podatności nie stanowi dowodu braku malware.
Nie zmieniano dystrybucji ani podpisywania Windowsa w celu ukrycia ostrzeżenia.

Źródło: [Microsoft — SmartScreen reputation for Windows app developers](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation).
